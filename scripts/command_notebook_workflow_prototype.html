What is this prototype presenting?
    
It presents the order of the work, the actions you will take, the messages you will see, and the structure of the saved report. It lets you try the design before the analysis program is built.

    
The finished tool will be Python commands and a guided notebook. A notebook combines explanations, small blocks of runnable code and their outputs. This HTML page is a practice version of that workflow.

    
The study compares prediction performance using fewer recorded EEG channels and optical groups. EEG records electrical activity; fNIRS uses light to measure blood-related signals. PhysioNet predictions concern recorded task conditions, not a person’s depression or actual stress.

    
The current target is the M4 Mac with 16 GB memory. Measure memory, disk use and processing time during development before final testing. The agreed two analyses nominally require 20,724 model fits before retries; none have been run by this demo.

    
The main analysis keeps and flags questionable finite signals. The predeclared sensitivity analysis repeats the comparison after excluding sections containing near-flat EEG. Counts and unavailable analyses must be reported honestly. Yi remains unavailable until its authorized files and procedure are verified.

    
Source decisions: Agree on the command and guided-notebook workflow and Choose preprocessing, models, and participant-separated evaluation.
